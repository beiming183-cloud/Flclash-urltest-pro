# 云端任务入口

这是可直接交给云端编程代理的任务。先读取根目录 AGENTS.md 和 `.agents/`，再读本目录全部规格。以 [UPSTREAM.md](UPSTREAM.md) 锁定的源码为基线，不升级内核或 SDK 来掩盖实现问题。

## 实现目标

用户在安卓手机使用 ChatGPT，当前组合是：

```text
手机 VPN / Clash
  → 指定机场中继 RF2-Relay-<机场>-<序号>
    → 固定住宅代理 HTTP 或 SOCKS5
      → ChatGPT / 测试服务
```

选优对象是完整链路，不能只测机场。IP1 始终使用 IP1 的住宅终端和预期出口；以后支持 IP2 时独立处理，不能跨 IP 自动救援。住宅的 `dialer-proxy` 必须引用具体中继名。

现有 URLTest 在故障后恢复有空挡；手机曾显示“网络提供非预期 SSL 证书”。该提示不能被直接归因于 URLTest。要同时实现稳定选路和可定位证书/握手问题的诊断。

## 交付要求

1. opt-in 稳定模式，保留原 URLTest / fallback 行为和普通配置兼容性。
2. 大池低频探索、候补反复验证、三个活跃候选持续检测；主用健康时保持，故障时尝试近期有效备用。
3. 在完整住宅代理建立路径内实现同次拨号备用重试；不会重放已发送的应用请求，不承诺搬移已建立 TCP。
4. UI 隐藏/关闭时逻辑由 native/Core 生命周期维持；不使用 Flutter 页面定时器充当后台控制器。
5. 检测针对指定候选，不临时修改用户的实际代理选择；显示当前链路、完整链路延迟、最近检测时间、稳定性、切换原因。
6. 详细日志导出按 [LOGGING](LOGGING.zh-CN.md)：4 MiB 轮转，10 分钟调试自动关闭，导出 ZIP 不超过 2 MiB，不含凭据、聊天内容或完整订阅路径。
7. 独立 Android 应用 ID / 名称，保留官方原版；不变更电脑配置。
8. 提交真实 Go、Flutter、生命周期与故障注入测试；构建独立 APK，并给用户真机验收清单。

## 工作阶段

按 [INTEGRATION](INTEGRATION.zh-CN.md) 的 P0–P5 分阶段提交。每阶段写 `docs/stability-pro/PROGRESS.zh-CN.md`：改了什么、测试输出、限制、下一阶段。最终在 README 将“尚未接入”改为真实完成情况，不能仅凭参考测试通过宣称 APK 修复成功。

先完成 P0：基线能否构建、独立包 ID、禁用不适合该 fork 的上游更新/发布/遥测配置；随后实现 Go 稳定组。UI 放在确定核心事件契约以后。

本仓库已将精确版本的 Core 源码纳入 Git；无需再初始化 Core 子模块。原上游工作流保留为 `.disabled` 文档，不自动跑跨平台构建或发布。唯一默认 CI 是轻量参考测试；完成产品接入后增加真正 Android 验证工作流。

## 不可用作“修复”的措施

- 关闭 TLS 验证、忽略证书、安装拦截证书。
- 故障时把住宅流量改为 DIRECT、机场直出或另一住宅出口。
- 每 30 秒全量测几百节点。
- 同时让 URLTest 和自定义调度器竞争选择同一组。
- 遇到一次失败就清空所有连接，或每次最快节点变化就换主用。
- 上传用户原始订阅、账号 token、真实 YAML 或未脱敏日志。

## 开发输入与真机界限

`fixtures/` 全是脱敏记录/保留地址。云端可完成模拟与工程测试，不能以此断言用户当前机场或住宅供应商兼容。用户真机本地导入自己的 IP1 文件，亲自登录 ChatGPT。最终需要 Wi-Fi / 蜂窝、锁屏、连续输出、网络切换的实际日志。
